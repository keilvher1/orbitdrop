# OrbitDrop architecture (shared reference for all workstreams)

OrbitDrop is a local file converter/editor. The core experience is: drag a file in
Finder/Explorer → hold a modifier → a radial menu appears near the pointer →
drop on a format/tool → (optionally adjust in a small editor) → the result is
written next to the original. The original is never moved, overwritten or deleted.

Spec source: the master prompt (Korean) given by the user. Video facts vs. product
decisions are kept apart in `docs/requirements.md`.

## Processes

```
┌──────────────── Electron main (apps/desktop/src/main) ────────────────┐
│ lifecycle · tray/menu bar · windows · settings · IPC (zod-validated)  │
│ FileRegistry (path ↔ fileId) · JobManager (core JobQueue)             │
│ HelperManager ──stdio NDJSON──► native helper (one process)           │
│ ProcessorPool ──utilityProcess──► processor-host.js (N workers)       │
└───────────────────────────────────────────────────────────────────────┘
      ▲ contextBridge (window.orbit = OrbitApi)
      │
 Renderer windows (React, sandboxed): picker · editor · jobs · settings · dropzone
```

* **Native helper** (`native/macos` Swift/AppKit, `native/windows` C++/Win32/OLE)
  owns *everything that happens during an OS drag*: global observation of the
  drag + modifiers, the single wheel window (visual + drop target in the same
  window), hit-testing, highlight, and accepting the drop (Copy only). It reports a
  validated `drop` message to main exactly once per session. Protocol:
  `packages/contracts/src/helper-protocol.ts`.
* **Main** never registers its own drop target for the wheel and never draws the
  wheel during OS drags. After a `drop` it validates paths (`@orbitdrop/core/node`
  `validateInputFile`), creates a `FileSelection`, then either submits jobs
  (non-interactive conversions) or opens an editor window. Window creation/focus
  happens on the next tick, after the helper has already returned from its drop
  callback.
* **Processor workers**: Electron `utilityProcess` running
  `out/main/processor-host.js` (source `apps/desktop/src/main/processing/host.ts`),
  which calls `@orbitdrop/processors` (`ProcessorApi` in
  `packages/contracts/src/processor-protocol.ts`). Messages:
  `MainToProcessorMessage` / `ProcessorToMainMessage`. One job at a time per
  worker; pool size = `settings.processing.concurrency`. A crash fails the job
  with `WORKER_CRASHED` (JobQueue retries once), restarts the worker and runs
  `cleanupTempFiles(dir, jobId)`.
* **Renderer**: one React bundle; each window asks `getWindowContext()` to know
  what to show. Never receives absolute paths; works with ids.

## Pipeline (same for global drag, Drop Zone, open dialog)

`FileSelection` (main validated files, fileIds) → `submitAction({selectionId, actionId, options})`
→ either `{kind:'jobs'}` (one job per file; merging actions → one job) or
`{kind:'editor', editorId}` → editor previews (`requestPreview`, seq-ordered) →
`commitEditor` → job → `JobSnapshot` updates (`onJobsChanged`) → outputs
(revealable by `outputId`).

Capabilities: `@orbitdrop/processors.probeEngines()` measures what the bundled
engines can do → `@orbitdrop/core.buildCapabilitySnapshot(probe)` →
`supports(snapshot, actionId, input)`; menus for the helper and the picker are
built only with `buildHelperMenus` / `buildWheelMenu` / `adjustMenuForFileCount`.
Disabled sectors are shown greyed with a reason; nothing runs unless supported.

## Drag session states

`Idle → PotentialDrag → AwaitingPayload → WheelActive → DropCommitted → (Editing | Processing) → Completed | Failed | Cancelled`

* Helper: Idle → PotentialDrag (left button down + movement + a real drag
  signal, e.g. macOS drag-pasteboard changeCount) → AwaitingPayload (modifier held:
  neutral wheel shown, "drop here" capsule; file data not assumed yet) →
  WheelActive (real drag-enter with file URLs / CF_HDROP; menu chosen from the
  extension map; sector order frozen for the session) → drop on an enabled,
  armed sector → `drop` message, wheel hidden. Esc / drag end / exit / parent EOF
  / sleep → `cancelled`, wheel hidden.
* Main: `DragSessionTracker` (core) accepts one drop per session, ignores
  duplicates, late messages and messages from a previous helper instance.
* Releasing the modifier does not close an active wheel. Hover never commits.
  An external mouse-up only cleans up.

## Coordinates & geometry

Global DIP, top-left origin, y down; angles in degrees, positive = clockwise.
`packages/contracts/src/geometry.ts` (spec) and `packages/core/src/geometry.ts`
(reference implementation: `hitTestWheel`, `placeWheel`, `isArmed`).
`tests/fixtures/wheel-golden.json` (generated by `scripts/gen-golden.mjs` from the
TS reference) is consumed by the Swift and C++ unit tests so all implementations
agree. macOS converts from bottom-left points; Windows from physical pixels per
monitor (Per-Monitor DPI Aware v2).

## Files & output safety

* Inputs are validated and sniffed by header (`validateInputFile`). Folders,
  unknown types, empty files, oversized files, cloud placeholders and symlink
  loops are reported with an `ErrorCode`.
* Outputs: `writeOutput(dir, desiredName, jobId, write)` — temp file in the target
  folder, exclusive commit via hard link (fallback `copyFile(COPYFILE_EXCL)`), free
  name `name (2).ext`… Never overwrites. Temp files are tagged with the job id and
  cleaned on failure/cancel/crash.
* Naming (`packages/core/src/naming.ts`): `Page 001.pdf → Page 001.jpg`,
  multi-page `report-p001.jpg`, tools `photo Cropped.jpg`,
  `photo Cropped With Background.png`.
* Read-only folder → `OUTPUT_DIR_NOT_WRITABLE` → main offers a folder picker and
  resubmits (`retryJobElsewhere`). No privilege escalation.
* Logs never contain document contents; avoid full paths in logs (job ids, codes).

## Shared paths and names

* Helper binaries are staged at `apps/desktop/resources/helper/<platform>-<arch>/`
  (`OrbitDropHelper` on macOS, `OrbitDropHelper.exe` on Windows) by
  `scripts/build-native-{mac,win}.mjs`. Main looks there in dev and at
  `process.resourcesPath/helper/` when packaged. `ORBITDROP_HELPER_PATH` is a
  dev-only override: packaged builds ignore it, and workers never inherit an
  `ORBITDROP_IMAGEIO_HELPER` that main did not set itself. Otherwise any
  same-user process could `launchctl setenv` a binary that macOS would then run
  with OrbitDrop's Accessibility/Input Monitoring grants.
* macOS helper optional codec mode (P2 HEIC):
  `OrbitDropHelper imageio --probe` → JSON `{"decode":["heic",…],"encode":["heic",…]}`;
  `OrbitDropHelper imageio --decode <in> --out <out.png>`;
  `OrbitDropHelper imageio --encode heic --quality <0..1> <in.png> --out <out.heic>`.
  Processors find it through `ORBITDROP_IMAGEIO_HELPER` (main sets it for workers).
* Tray icons: `apps/desktop/resources/tray/trayTemplate.png` (+ `@2x`) on macOS,
  `apps/desktop/resources/tray/tray.ico` on Windows. App icon:
  `apps/desktop/build/icon.{icns,ico,png}`. Main must tolerate missing icons in dev.
* Locales: `apps/desktop/src/shared/locales/{ko,en}/{main,ui,errors}.json`.
  Korean is the default UI language.
* Preview images: custom protocol `orbit-preview://p/<token>` (main), CSP allows it.
* Settings: `app.getPath('userData')/settings.json` (versioned, `migrateSettings`).
* Smoke test (used by packaging to verify installed builds): the app accepts
  `--smoke-test`. It probes the engines in a worker, starts the helper and waits
  up to 5 s for `ready`, converts a generated PNG to JPG and a generated PDF to PNG
  in a temp folder through the real job pipeline, and opens the About window
  **hidden** through the real WindowManager (same BrowserWindow options, `loadFile`
  from app.asar, preload, CSP, IPC; never shown or focused) and requires it to
  render within 15 s. It prints one line
  `ORBITDROP_SMOKE {"ok":bool,"probe":{…},"helper":{…},"conversion":{…},"pdfConversion":{…},"window":{"ok":bool,"loaded":…,"rendered":…,"error":…}}`
  to stdout, and exits 0 (ok, which requires both conversions and the window) or 1.
  The window check exists because the first 0.1.0 package had blank windows (a fuse
  blocked `file://` inside app.asar) while the window-less smoke test passed.
* Test switches (`ORBITDROP_E2E*`, `ORBITDROP_HELPER_PATH`, `ORBITDROP_DISABLE_HELPER`,
  `ORBITDROP_NO_TRAY`, `ORBITDROP_USER_DATA_DIR`, `ORBITDROP_PDFJS_DIR`) work in
  unpackaged builds only: packaged builds ignore them, and main does not pass them on
  to workers ([development.md](development.md)). Playwright E2E runs against `out/`
  (packaged fuses disable `--inspect` anyway).
* Preview memory: when the last editor closes, main sends `clearPreviewCaches`
  to the aux worker, which drops its cached decodes.

## Conventions

* TypeScript strict; Node 22.12+ (dev uses Node 24; Electron 44.9.0 bundles Node 24.x).
* Cross-platform scripts are Node `.mjs` files — no POSIX-only shell in package scripts.
* Tests must re-read real outputs (decode the image, count PDF pages, check pixels),
  not restate the implementation.
* Never claim a real Finder/Explorer drag is verified from unit tests or builds;
  `docs/support-matrix.md` separates implemented / auto-verified / GUI-verified /
  unverified / unsupported.
