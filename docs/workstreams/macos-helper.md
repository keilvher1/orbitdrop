## 3. Design

### Process model
* `NSApplication` with `.accessory` activation policy (plus embedded `LSUIElement`): no Dock icon, no menu bar,
  never activates. Run loop on the main thread; all AppKit/controller work is `@MainActor`.
* **stdin**: dedicated thread, `read(2)` → `LineFramer` (hard 1 MiB per line, oversized lines discarded without
  buffering) → strict parse off-main → hop to main. EOF or read error → parent gone → hide wheel, send
  `cancelled parentRequest` for an open session, flush, `exit(0)`.
* **stdout**: encode on the caller, write on a private serial queue (`write(2)`, EINTR/EAGAIN handled), so a slow
  reader never blocks the main thread or a drop callback. `SIGPIPE` ignored; EPIPE ⇒ treated as parent gone.
* `SIGTERM`/`SIGINT`/`SIGHUP` → same clean exit. Stop message (`v:1,type:"shut…"`) → same. Signals are handled on
  a background queue, and an exit watchdog `_exit(0)`s the process 3 s after main is gone (EOF, EPIPE, signal) if
  the AppKit thread is wedged and cannot run the graceful exit — a dead process's windows vanish, so no wheel can
  be stranded.
* App Nap: a `.userInitiatedAllowingIdleSystemSleep` activity is held only while observation is enabled
  (keeps the 60 Hz poll punctual; idle sleep stays allowed).

### Observation without permissions (GlobalDragObserver)
* `NSEvent.addGlobalMonitorForEvents([.leftMouseDown, .leftMouseDragged, .leftMouseUp])` — mouse events only,
  **no key-event monitoring** (key monitors would need Accessibility).
* Modifiers: `NSEvent.modifierFlags`, polled at 60 Hz **only while the left button is down or a session is
  open**; mapped to `shift / alt (Option) / control / command` (Caps Lock, Fn ignored).
* **The mouse-down carries the modifiers held at that instant** (`mouseDown(point, held:)`), atomically, as a
  baseline — not as a press. (Before the audit fix the observer emitted the mouse-down and then a forced modifier
  update, so a combo held *before* clicking looked like a press and opened the wheel.)
* The pointer is polled with the modifiers while the button is down (hardening pass), so neither the start of a
  session nor where the wheel opens depends on the global monitor receiving the dragged events of another app's
  drag loop.
* A real OS drag is confirmed by `NSPasteboard(name: .drag).changeCount` moving after the mouse-down (contents
  are never read there; reads stop once confirmed). `NSEvent.pressedMouseButtons` backs up a missed mouse-up.
* Escape: polled with `CGEventSource.keyState` **only if Input Monitoring was already granted**. The TCC status
  (`CGPreflightListenEventAccess()`, never requested) is queried **off the main thread** at start, on each
  `configure`/`queryPermissions` and every 60 s while observing, and cached — never inside a mouse callback.
  Without it, Esc is recognised indirectly (see cleanup).
* The display list (`NSScreen.screens` → DIP) is cached and refreshed on `configure` and screen-change
  notifications, not per mouse-down.
* All system reads go through an injectable `DragInputSource` (`SystemDragInputSource` in production), so tests
  replay AppKit's real orders (monitor callback, 60 Hz ticks) through the real observer.
* Callbacks only update state; no file access, no blocking I/O, no logging of positions or keys.

### Session state machine (DragSessionController, pure)
`Idle → PotentialDrag → AwaitingPayload → WheelActive → (drop | cancelled) → Idle`

* **PotentialDrag** = button down + ≥ 3 pt movement + drag-pasteboard change. Internal: never reported, so
  ordinary drags without the modifier produce **no messages at all**.
* **AwaitingPayload**: a modifier *press during the drag* (after the mouse-down, incl. before the pasteboard
  confirmed the drag) that makes the held set exactly equal to a configured combo, followed by **40 ms of stable
  modifiers** (`modifierSettle`; Shift then Option pressed a few ms apart opens tools directly, without a
  convert flash; releasing inside the window abandons it). A combo already held at the mouse-down is the
  baseline and does **not** open the wheel (Shift-click-to-select-then-drag in Finder stays undisturbed;
  releasing and pressing again opens it) — verified through the real observer with a scripted input source.
  Neutral wheel at the pointer, clamped into the display's visible frame (`placeWheelOnDisplays`); **center
  fixed for the session**. `state AwaitingPayload {mode}`.
* Neutral wheel without a drag-enter: once the pointer has travelled ≥ 12 pt over the disc and AppKit still sent
  no `draggingEntered` for 400 ms (`noEnter`), the drag carries nothing the wheel registered for (e.g. a window
  tab) — the wheel is hidden and the session `cancelled invalidPayload`.
* **WheelActive** on the first real `draggingEntered`: items classified once, menu frozen per mode for the
  session (a `configure` arriving mid-drag applies to the next session). `state WheelActive {mode, menuKey|null,
  fileCount}`; `menuKey: null` = unsupported items, shown with `strings.unsupportedFolder` / `unsupportedNonFile` /
  `unsupportedVirtual` when main sent them (folder; text/URL data; file promises, Mail/Photos items), else
  `strings.unsupported`.
* Mode switch: pressing keys that complete the *other* combo (e.g. Shift then Option) switches convert↔tools
  and **restarts arming**; releasing keys never changes the mode; releasing all modifiers keeps the wheel.
* Selection: hit-test in the y-down space; dead zone and outside never select; a sector is selectable only
  once armed (moved ≥ `armDistance` from the activation point, or passed through the dead zone). Styles:
  `hover` (unarmed), `active` (orange, copy), `rejected` (disabled sector or source without Copy: dashed outline,
  reason in the capsule).
* **Drop** only in `performDragOperation`, only on an enabled armed sector, only if the source mask contains
  Copy; returns **Copy, never Move**. The drag pasteboard is read **once**, in the first `draggingEntered`
  (paths become owned Strings there; the only possible file-system call is resolving a rarely used
  file-reference URL); re-entries and `performDragOperation` reuse that payload — no pasteboard, TCC or
  file-system call happens in the drop callback. `drop` sent once, session closed, wheel hidden on the next
  run-loop turn. A second perform/late callback cannot produce another drop.
* **Every announced session ends with exactly one terminal message, `drop` or `cancelled`.** The helper never
  sends `state Idle` (per the contract, `Idle` would also end the session).
* Session ids: `m<pid>-<random base36>-<counter>` — unique across helper restarts (even a reused pid),
  `^[A-Za-z0-9_-]{1,64}$`.

### Cleanup paths (all end with `cancelled` + hide)
| Trigger | Behaviour / reason |
|---|---|
| global mouse-up | grace timer (600 ms if the pointer was on an acceptable sector — the drop callback can lag the monitor event — else 150 ms), then `dragEnded` (or the last rejection reason) |
| `draggingExited` with the pointer still over the disc | the drag ended over us (Esc in the source, or released on a rejecting spot): after 150 ms without re-entry → `escape` if the button is still down, else `disabledSector` / `outsideRing` / `invalidPayload` / `dragEnded` |
| `draggingExited` with the pointer outside | wheel stays; re-entry allowed |
| `draggingEnded`, Esc (when permitted) | `dragEnded` / `escape` |
| sleep, screens asleep, user switch, screen locked (`com.apple.screenIsLocked`, distributed, delivered immediately) | `sleep` |
| display under the wheel disappears | `error` (never leave a stranded window) |
| `cancelSession{id}` / `configure{enabled:false}` / stdin EOF / stop / SIGTERM | `parentRequest` |
| next mouse-down while a session is open (missed mouse-up) | `dragEnded` |
| neutral wheel, pointer moved over it, no `draggingEntered` within 400 ms | `invalidPayload` |
| release beside the ring / in the panel's transparent corners | not ours: the drag goes to the window underneath (Finder's normal drop); the session ends via mouse-up → `dragEnded` |

### The wheel window and drop target
`WheelPanel`: borderless + `.nonactivatingPanel`, `isFloatingPanel`, level `.popUpMenu`, `[.canJoinAllSpaces,
.fullScreenAuxiliary, .transient, .ignoresCycle]`, `hidesOnDeactivate=false`, transparent, `hasShadow = true`
(window server shadow), `canBecomeKey/Main = false`, shown with `orderFrontRegardless()` — never steals focus
or ends the source drag. It is **created hidden (`defer: false`) with its drag types registered when
observation is enabled**, not in the middle of the first drag. `WheelView` (flipped) both **draws the wheel and
is the `NSDraggingDestination`** (one window, one owner of visual + input). Registered types: file URLs,
file-promise types (so promises are recognised as unsupported) and common non-file types
(text/URL/image/PDF/RTF/HTML) so a non-file drag shows "unsupported". Hit-testing uses view-local flipped
coordinates mapped through the panel layout (`WheelPanelLayout.global`; the golden `coords.mac` pointers pass
150/150 through this exact chain with a real `WheelView`).

#### Hit shape: a drop beside the ring must stay the source app's normal drop (#11)
Before the fix the panel was placeWheel's 408 × 408 `windowFrame` (24 pt margin around the 360 disc), made
explicitly hit-testable (`ignoresMouseEvents = false`) and painted with a shadow, so a release up to ~24 pt
beside the ring (~75 pt at the diagonals) became our `outsideRing` cancel instead of Finder's drop on whatever
was underneath — contrary to spec §4. Now:
1. **Smaller window**: the panel is only the disc's bounding square plus a 6 + 26 pt caption strip
   (`WheelPanelLayout`: below the disc, or above it when the wheel is pushed against the bottom of the work area,
   or none if neither fits). placeWheel's `windowFrame` (with `windowMargin`) is still computed for golden parity
   but no longer sizes the window.
2. **Alpha 0 outside the hit shape**: the live view paints nothing outside the disc and the caption pill (the
   disc gets an invisible 1/255 floor so gaps and dead zone always stay in the shape). Verified offscreen: a
   `cacheDisplay` of the real view has 0 non-transparent pixels outside disc ∪ pill.
3. **`ignoresMouseEvents` is never assigned.** AppKit's behaviour for non-opaque windows: while the property has
   not been set explicitly, the window server routes mouse events — and the drag manager picks drop destinations
   — past fully transparent pixels; assigning `false` makes the whole rectangle opaque to events. (The SDK headers
   carry no doc comment; this is AppKit's long-standing click-through behaviour for transparent windows. It cannot
   be observed without synthesized input, hence §8 step 9.)
4. **No painted shadow**: the shadow is the window server's (`hasShadow`, recomputed with `invalidateShadow()`
   after the panel is drawn and whenever the caption appears/disappears). Window shadows are outside the window
   and never hit-testable. Snapshots paint an equivalent shadow because they have no window server.
5. The caption pill is part of the hit shape **by design**: a release on the visible caption is our cancel
   (`outsideRing`), never Finder's. The pill is small, only visible while a sector is armed, and sits
   right under the ring where a deliberate Finder drop is unlikely.
If step 3 turned out not to hold for drags on some macOS version, the swallowed area is now limited to the four
corners of the disc's square and the caption strip beside the pill.

### Classification
Port of core `menuKeyForPaths` working on Unicode scalars (never `Character`, never normalization), ASCII-only
lower-casing, `/` and `\` both separators, trailing separator = folder. Because Swift `String ==` is canonical
equivalence, only ASCII extensions are looked up (map keys are `^\.[a-z0-9]{1,8}$`), keeping code-unit
semantics. Additionally unsupported, each with a reason that selects the capsule text: file promises → `virtual`
(`strings.unsupportedVirtual`), folders (URL trailing slash, trailing separator, or the off-main `stat` re-check)
→ `folder` (`unsupportedFolder`), text/URL/other data → `nonFile` (`unsupportedNonFile`), and unknown types,
relative paths or > 200 items → `strings.unsupported`. Precedence when mixed: virtual, folder, non-file. Each
optional string falls back to `unsupported` when absent or empty. Multi-file: non-batch sectors disabled with
`strings.multiFileUnsupported` (golden `fileCount`).
Online-only cloud files (hardening pass, parity with the Windows helper): the same off-main `stat` reads
`st_flags`; `SF_DATALESS` (iCloud Drive / File Provider dataless file) → `cloudPlaceholder` with the built-in text
"먼저 내려받으세요" / "Download it first" (no `configure` field yet; a later `strings.unsupportedCloud` is the lead's
contract change), no Copy anywhere, release → `cancelled: invalidPayload`. Nothing is opened or read, so nothing is
downloaded. A folder found by that stat wins over the cloud reason. The stat result arrives a few milliseconds after
the drag-enter; a drop made before it is still validated by main (`CLOUD_PLACEHOLDER`).

### Geometry: bit-exactness finding
Measured against Node 24.7 (V8, arm64) on 300 016 vectors: Darwin `hypot` differs from `Math.hypot` in 34 %,
Darwin `atan2` from `Math.atan2` in 17 %, a plain fdlibm port in 0.1 %. Disassembly of
`v8::base::ieee754::atan` in the shipped node binary shows clang fused multiply-adds (polynomial, id=2
reduction, both tail expressions). `JSMath` reproduces V8's `MathHypot` (Kahan) and fdlibm `atan2` with exactly
those FMAs (`addingProduct`, correctly rounded on arm64 and x86_64) → **0 mismatches**, so boundary points agree
bit for bit on both helper architectures.

### Protocol strictness
Hand-written strict decoding on `JSONDecoder` mirrors the zod schemas: unknown types/fields rejected, `v`
must equal 1, optional ≠ nullable, numbers finite and in range, safe integers, regexes (Id, ColorHex8,
extension keys), enums (action ids, menu keys, icons, modifiers), array/record limits. `configure.strings`
accepts the optional `unsupportedFolder` / `unsupportedNonFile` / `unsupportedVirtual` (≤ 60, not nullable;
88a209b). The 135-line parity corpus (`protocol-cases.json`, zod verdicts) is regenerated from the contracts by
`gen-fixtures.mjs`; the configure fixtures are built with desktop-main's own `buildConfigureMessage`. Findings:
* **zod 4.6.7 measures string `.min/.max` in Unicode code points** (a surrogate pair counts once) — the helper
  uses `unicodeScalars.count` everywhere (verified with emoji/flag/combining-mark cases).
* JSON level (hardening pass): Foundation accepts trailing commas (`{"a":1,}`, `[1,]`) and a UTF-8 byte-order
  mark, `JSON.parse` does not ⇒ rejected; Foundation refuses lone surrogate escapes (`"\ud800"`, which
  `JSON.stringify` emits for a split pair and zod accepts as one code point) ⇒ read as U+FFFD instead of dropping
  the whole `configure`. Documented, unreachable divergence: literals that underflow (`1e-400`; `JSON.stringify`
  writes `0`).
* Duplicate JSON keys: `JSON.parse` keeps the last, Foundation keeps the first ⇒ the helper **rejects** lines
  with duplicate keys (`JSON.stringify` never emits them) — the one intentional divergence from zod.
* Invalid lines are ignored and reported as `log warn` (field names only — never values or paths).
* Outgoing messages are validated before writing (ids, file lists 1…200, path length, line ≤ 1 MiB; a drop
  that would exceed the line limit is rejected as `invalidPayload`); free text is truncated to the schema limits.

### Rendering
CoreGraphics + CoreText, shared by the panel and `--render-snapshot`: translucent disc, thin outer ring, N
annular wedges with constant-width gaps (edges offset by gap/2) and exactly tangent rounded corners (radius
clamped for 12 sectors / small wheels), horizontal uppercase format labels, SF Symbols above tool labels
(`compress → arrow.down.right.and.arrow.up.left`, `metadata → tag`, `edit → slider.horizontal.3`,
`annotate → pencil.tip.crop.circle`, `background → photo.artframe`, `crop → crop`, `redact → eye.slash`),
disabled styling, active sector in the `sectorActive` token (light theme `#D4441C`, 50f61af) with white text,
center capsule (hovered action, disabled reason with Korean word-based wrapping up to 3 lines, drop hint, file
count or size), high-contrast extras (outlines, thicker ring), appear (fade from 0.2 → 1 over `appearMs`; the
panel is never at alpha 0, so it is a drop destination from its first frame) / disappear (90 ms fade). Retina
via the backing scale; snapshots at `--scale 2`. A WCAG test checks every text/fill pairing per theme.

* **Secondary hint (spec §8, #16)**: while a sector is armed, a one-line caption pill outside the ring — in the
  panel's caption strip below the disc (above it near the bottom edge) — repeats the choice (`JPG`, or why the
  hovered sector is refused), so it stays readable when the drag image covers the sector and the capsule. Hit
  shape: see "Hit shape" above (the pill is a cancel by design; the rest of the strip is transparent).
* **VoiceOver**: when the armed choice changes, an `NSAccessibility` announcement (`announcementRequested`,
  high priority) speaks it — the sector label, or `label: reason` for a refused one — once per change, only
  while VoiceOver runs. The view's accessibility value mirrors the capsule.
* **Unsupported drags and Reduce Transparency** (hardening pass): VoiceOver also hears why dragged items cannot
  be used (the capsule's reject text), once per change. With System Settings ▸ Accessibility ▸ Reduce
  transparency on, the disc is drawn opaque in the same palette (read when a wheel is shown); everything outside
  the disc stays alpha 0.
* **Reduce Motion at runtime (#18)**: the helper observes `NSWorkspace.accessibilityDisplayOptionsDidChange`.
  If the OS turns Reduce Motion on after main's last `configure` said `reduceMotion: false`, the helper follows
  the OS (no appear/disappear animation) **until the next `configure`**, whose value wins again (main resolves
  "system" itself; an explicit "on" is never weakened by the OS turning it off).

Screenshots (`docs/screenshots/`, rendered offscreen by the staged binary over a stand-in desktop gradient,
with the painted stand-in for the window shadow; canvas = panel + 24 pt margin, i.e. 408 × 440 pt):
`macos-helper-pdf-convert.png` (PDF → JPG active, caption "JPG"), `macos-helper-jpg-convert.png`,
`macos-helper-tools.png` (Korean, "1.2 MB" capsule), plus `-tools-en`, `-disabled-reason` (HEIC reason in the
capsule and the caption), `-multifile`, `-neutral`, `-dark`, `-high-contrast`.

### `imageio` mode (P2 HEIC) — stable contract used by packages/processors
```
OrbitDropHelper imageio --probe
OrbitDropHelper imageio --decode <in|-> --out <out.png|-> [--no-orient] [--max-pixels N]
OrbitDropHelper imageio --encode <heic|avif|jpeg|png|tiff|gif|bmp> --quality <0..1> <in|-> --out <out|-> [--max-pixels N]
```
1. `--probe` prints exactly one JSON line `{"decode":[…],"encode":[…]}` (the last stdout line) using OrbitDrop
   format names. Encode support = listed by `CGImageDestinationCopyTypeIdentifiers` **and** a real in-memory
   encode→decode round trip. This Mac: decode `jpeg png webp gif tiff avif heic bmp`, encode
   `jpeg png gif tiff avif heic bmp` (no WebP encoder in ImageIO).
2. Exit code 0 = success; 1 = decode/encode/IO failure; 2 = usage (e.g. `--quality 70`); 3 = encoder unavailable.
   With a file `--out`, one JSON line `{"ok":true,"width":W,"height":H}` or `{"ok":false,"error":CODE,"message":…}`;
   the output is written atomically. `-` reads stdin / writes the image bytes to stdout (no JSON then).
3. `--decode` uses the primary image, applies EXIF/HEIF orientation to the pixels and writes an **upright PNG
   without an orientation tag** (keeps the ICC profile). Pixel limit default 268 402 689 (sharp's).
4. `--quality` is a fraction **0…1** (`kCGImageDestinationLossyCompressionQuality`); no metadata is written.
Covered by `ImageIOTests` and `HelperProcessTests.testImageIOContractUsedByProcessors`.

## 4. Permission findings
* The chosen method needs **no** Accessibility, Input Monitoring or Screen Recording permission. `permissions`
  reports `accessibility` and `inputMonitoring` with `required:false`; `ready.globalDrag.available` is true when
  a global mouse monitor can be installed.
* Measured: installing/removing the global mouse monitor, `AXIsProcessTrusted()` and
  `CGPreflightListenEventAccess()` never showed a prompt. Both reported `granted:true` here only because TCC
  attributes a child process to its responsible app (the terminal running the agent); spawned by OrbitDrop.app
  the values will be OrbitDrop's own (normally false) — nothing changes functionally.
* Not measurable by an agent (no synthesized input allowed): whether global `leftMouseDragged`/`leftMouseUp`
  are delivered during a Finder drag, the drag-pasteboard change timing, `draggingEntered` on a panel shown
  mid-drag, Esc/exit sequencing, real Copy-only behaviour in Finder. → §8.

## 6. Signing & distribution
* Local: ad-hoc signature with the hardened runtime (`codesign --force --options runtime --timestamp=none
  --identifier com.orbitdrop.helper -s -`), verified with `codesign --verify --strict`.
* Distribution: sign `Contents/Resources/helper/OrbitDropHelper` with the app's **Developer ID Application**
  identity, `--options runtime --timestamp`, **no entitlements** (no JIT, no library validation exceptions, no
  Apple Events, no sandbox needed); sign it *before* the app bundle and notarize the whole app. With
  electron-builder/@electron/osx-sign, exclude it from `entitlementsInherit` (e.g. `optionsForFile` returning
  no entitlements) so Electron's JIT entitlements are not inherited. `node scripts/build-native-mac.mjs --sign
  "Developer ID Application: …"` produces correctly signed binaries for that flow.
* TCC: a spawned helper is attributed to OrbitDrop.app (responsible process), so even future permissions would
  be shown for OrbitDrop, not for the helper.

## 7. Notes for other workstreams (also in the final report)
* **desktop-main** — spawn `OrbitDropHelper` (no args, or `--stdio`) from `resources/helper/darwin-<arch>/` with
  `stdio: ['pipe','pipe','pipe']`; read stdout as NDJSON (`parseHelperLine`), stderr is diagnostics. `ready`
  arrives first (≈ 50 ms release; allow 5 s), *before* any configure; nothing is observed until a `configure`
  with `enabled:true`. Re-send `configure` on every settings/capability/theme/locale change (full message).
  Keep stdin open for the helper's lifetime; to stop: the stop message or close stdin — the helper hides the
  wheel, reports an open session as `cancelled parentRequest` and exits 0 within ~100 ms. Treat a non-zero exit
  or a missing `ready` as a crash and restart with backoff (session ids never repeat). Every announced session
  ends with exactly one `drop` or `cancelled`; `state Idle` is never sent. Do window/focus work on the next tick
  after `drop` (the helper already returned from the OS callback). The helper now accepts — and main may start
  sending — `strings.unsupportedFolder` / `unsupportedNonFile` / `unsupportedVirtual`. When the OS turns Reduce
  Motion on after a `configure` with `reduceMotion: false`, the helper follows the OS until the next `configure`;
  re-send `configure` when the OS setting changes if main wants its own resolution to apply.
* **lead / contracts** — the macOS panel is no longer placeWheel's `windowFrame` (disc + `windowMargin`): it is
  the disc's bounding square plus a caption strip (§3 "Hit shape"). Consider updating the `windowMargin` /
  `windowFrame` comments in `packages/contracts/src/geometry.ts` ("room for the shadow" is now the window server's
  shadow outside the window); golden parity of `placeWheel` is unchanged.
* **settings (desktop-main / desktop-renderer)** — on macOS reject or warn about modifier combos containing
  **Control or Command**: AppKit converts them into Link/Generic drag operations, so the source offers no Copy
  and the helper (correctly) refuses every drop. Combos must differ (the helper logs a warning otherwise).
* **packaging-docs** — ship both `darwin-arm64` and `darwin-x64` helpers via extraResources; signing as §6;
  helper bundle id `com.orbitdrop.helper` (embedded Info.plist) — rename to the app's id prefix if desired.
* **processors** — the `imageio` contract in §3 is stable and tested.

## 8. Manual GUI verification (user) — the native drag PoC
Prerequisite: `node scripts/build-native-mac.mjs --arch arm64` then, in Terminal at the repo root:
`node --import tsx native/macos/scripts/poc-harness.mjs --guided` (add `--locale en` for English labels). It prints
one line per event; nothing is converted. Keep a test folder with `Page 001.pdf`, two JPGs, a PNG, a TXT and a
sub-folder. Record OS version, display setup and pass/fail per step.

How to read the harness (hardening pass): every helper line is validated with the real zod schema, and every
session against the rules main relies on (AwaitingPayload first, WheelActive before a drop, exactly one `drop` or
`cancelled`, nothing after it). Any violation is printed at once with `!!`; a wheel open longer than 20 s is a
`??` warning (fine during a long drag, a stuck wheel otherwise). `--guided` walks through the steps below: it
shows what to do and what to expect, waits for Enter, gives an
automatic verdict from the helper's messages (`✔` / `✘ reason`), asks a y/n question for what only your eyes can
judge, and prints a table of all steps. Ctrl+C ends either mode with a summary whose last line is
**`RESULT: PASS`** or **`RESULT: FAIL`** (exit code 0 / 1). Without `--guided` the harness only watches; follow
the steps yourself and judge the visual parts.

1. **Start**: harness prints `ready … global drag available` and `permissions (none required)`. No permission
   dialog appears now or later; System Settings ▸ Privacy & Security ▸ Accessibility / Input Monitoring do not
   gain an OrbitDrop entry.
2. **Finder drag + Shift → wheel**: in Finder start dragging `Page 001.pdf`; while moving, press and hold
   **Shift**. Expected: the wheel appears centered on the pointer within ~0.1 s; Finder stays the active app
   (menu bar still "Finder"); the drag image keeps following. Harness: `wheel shown (convert)`, then after a
   small move `convert menu for pdf, 1 file(s)`. Sectors: DOCX (top), JPG (right), PNG (bottom), TXT (left).
3. **PDF → JPG drop**: move onto **JPG** → it turns red-orange, the capsule shows `JPG`, and a small `JPG`
   caption appears **under the ring** (still readable when the drag image covers the sector); the cursor shows
   the green "+" (Copy). Release. Expected: wheel disappears immediately; harness prints exactly one
   `DROP convert.jpeg (convert, copy) on 1 file(s): Page 001.pdf`; the PDF is still in its folder (not moved).
4. **Arming / dead zone**: open the wheel again and release over the center capsule → no DROP, harness
   `cancelled: dragEnded`; the drag image slides back; the file is unchanged.
5. **Option+Shift → tools wheel**: drag a JPG and press Shift+Option together (any order within a few tens of ms)
   → the tools wheel appears directly, with **no flash of the convert wheel**; pressing Option a moment after
   Shift switches convert → tools. Expected: 7 tool sectors with icons (압축/COMPRESS on top). Drop on 자르기/CROP →
   `DROP tool.crop (tools, copy)`. Also: hold Shift *before* clicking the file, then drag → **no wheel**
   (`wheel shown` is not printed); release Shift and press it again during the drag → the wheel opens.
6. **Modifier release keeps the wheel**: open the wheel with Shift, release Shift, move to PNG, drop →
   `DROP convert.png`.
7. **Esc**: open the wheel, keep the button down with the pointer over the wheel, press **Esc** → Finder cancels
   its drag, the wheel disappears within ~0.2 s, harness `cancelled: escape`. Repeat with the pointer *outside*
   the wheel: without Input Monitoring the wheel stays until you release the button, then `cancelled: dragEnded`.
   (If the terminal running the harness has Input Monitoring — this Mac's does, the helper inherits it — Esc is
   seen directly and both cases report `escape`; OrbitDrop.app itself normally lacks it. Note what you see.)
8. **Exit / re-entry**: open the wheel, drag out of it (wheel stays, highlight clears), come back in, drop on
   JPG → exactly one DROP. Drag out and drop on a Finder folder instead → Finder performs its normal move/copy,
   the wheel disappears, harness `cancelled: dragEnded`, no DROP.
9. **Beside the ring = Finder's drop (#11, the key hit-shape check)**: arrange a Finder window so that one of its
   folders lies just outside the wheel. (a) Open the wheel, move the pointer ~10–20 pt *outside* the outer ring
   (left, right, above) onto the folder and release → Finder must highlight the folder while hovering and then
   move/copy the file into it as usual; the harness prints `cancelled: dragEnded` (**not** `outsideRing`). (b) Same
   in a **diagonal corner** of the wheel's square (~30–60 pt outside the ring at 45°). (c) Same just *below* the
   ring beside the caption pill (when no sector is armed, no pill is shown). Expected for all: the folder under the
   pointer receives the drop. Releasing **on** the visible caption pill is our cancel by design (`outsideRing`).
   If (a)/(b) instead print `outsideRing` and Finder does nothing, report it: the transparent-area pass-through
   does not apply to drags on this macOS version.
10. **Disabled sector**: drag a JPG with Shift (HEIC is disabled in the harness configuration), hover HEIC →
    dashed grey highlight, capsule and caption show the reason; release there → no DROP, `cancelled: disabledSector`.
11. **Unsupported drags, specific texts**: press Shift while dragging (expected capsule text — repeated in the caption below the ring, since a wide drag image can cover the capsule — ko/en):
    selected text from TextEdit/Safari → "파일이 아님"/"Not a file"; a folder (or an `.app`/`.rtfd` package) →
    "폴더는 처리할 수 없음"/"Folders aren’t supported"; a Photos item, Mail attachment or Safari image (file promise) →
    "먼저 파일로 저장하세요"/"Save it as a file first"; a `.txt` file → "지원하지 않는 파일"/"Unsupported file". No
    sector highlights; release → `cancelled: invalidPayload`. (The harness sends main's wording from the generated
    configure fixture — `node --import tsx native/macos/scripts/gen-fixtures.mjs` refreshes it.)
12. **Neutral wheel without a drop target**: drag a Safari tab (or a window tab) and press Shift → if the drag
    carries nothing the wheel accepts, the neutral wheel disappears ~0.4 s after you move over it
    (`cancelled: invalidPayload`); with a file drag it never disappears on its own.
13. **Multiple files**: drag two JPGs → capsule `2개 파일`/`2 files`; tools wheel shows EDIT/ANNOTATE/ADD BG/
    CROP/REDACT greyed with `한 번에 한 파일만`; COMPRESS works → one DROP with 2 files.
14. **Rapid repeated drops**: 10 quick PDF→JPG drags in a row → 10 DROP lines, 10 different session ids, no
    `DUPLICATE` warning, no wheel left on screen.
15. **No Copy offered** (known limitation check): open the wheel with Shift, then also hold **Command** (the
    held set {Shift, Command} matches no combo, so the wheel simply stays) → hovering a sector shows the rejected
    dashed style and a release drops nothing (`cancelled: invalidPayload`); releasing Command restores the
    Copy highlight. Holding Command+Shift *before* pressing never opens the wheel (exact-combo rule).
16. **Retina / secondary display / edges**: repeat steps 2–3 on an external display (different scale), at all
    four screen edges and corners, near the menu bar and the Dock, and with a display arranged left/above (negative
    coordinates). Expected: the wheel stays fully inside the visible area (shifted away from edges); near the bottom
    edge the caption moves **above** the disc; when shifted, a sector only selects after a small (≥ 6 pt) move;
    the highlighted sector always matches the drawn one.
17. **Spaces / full screen / Mission Control / Stage Manager**: repeat over a full-screen app and on another Space
    → the wheel appears above it and the full-screen app keeps focus. Start Mission Control during a drag (F3, or
    drag to the top of the screen) → the wheel hides while it is up and comes back after; with Stage Manager on, the
    wheel is never put into a stage.
18. **Accessibility**: (a) Reduce Motion: with the harness running (no `--reduce-motion`), turn on System Settings
    ▸ Accessibility ▸ Display ▸ Reduce motion *while the harness runs* → the next wheel appears/disappears without
    fading (the helper follows the OS until main's next configure); restart the harness → it fades again until the
    OS setting is toggled. (b) VoiceOver (⌘F5): open the wheel and hover JPG, then HEIC → VoiceOver speaks "JPG",
    then "HEIC: …reason"; drag a folder with Shift → it speaks the folder text once; note whether a background
    helper's announcements are spoken. (c) `--theme highContrast` and `--theme dark` → palettes as in the
    screenshots; in high contrast the caption pill's outline stays inside the pill. (d) Reduce transparency (same
    pane) → the next wheel has an opaque disc (no desktop showing through); the corners of its square stay
    see-through and a drop there still reaches Finder (as in step 9).
19. **Parent exit**: open the wheel and press Ctrl+C in the harness (or kill it) → the wheel disappears at once
    and the helper exits; no window remains (also try closing the Terminal window).
20. **Intel Mac (if available)**: repeat 2–3 with `--arch x64` on Intel hardware (only Rosetta-tested so far).
21. **Screen lock during a drag** (hardening): open the wheel, keep the button down and lock the screen
    (Ctrl+Cmd+Q or the Touch ID key); unlock → no wheel on screen, harness `cancelled: sleep`. Same for closing the
    lid / Apple menu ▸ Sleep with the wheel open (`sleep`), and — with a second display — unplugging the display the
    wheel is on (`cancelled: error`, or the wheel stays usable if macOS moved it to the remaining display).
22. **Secure keyboard entry** (needs your eyes; cannot be measured without real input): turn on Terminal ▸ Secure
    Keyboard Entry, keep Terminal frontmost and drag the folder proxy icon from its title bar with Shift → note
    whether the wheel opens (modifier polling under Secure Event Input; it will say "folders aren’t supported", that
    is fine) and whether Esc over the wheel is seen. Turn the option off afterwards.
23. **Second display with a different scale** (if available): open the wheel on a 1× display after using it on the
    Retina display (and back) → labels and the ring are crisp on both, and the highlighted sector matches the pointer
    exactly (hit-testing is in points).
24. **Online-only iCloud file** (hardening, parity with Windows): in iCloud Drive pick a PDF or JPG that shows the
    cloud icon (not downloaded; Finder ▸ Remove Download makes one), drag it with Shift and hover the wheel → after a
    moment the capsule says "먼저 내려받으세요"/"Download it first", no sector turns orange; release on a sector →
    `cancelled: invalidPayload`, no DROP, and the file **still shows the cloud icon** (nothing was downloaded).

## 9. Known limitations / open issues
* Real Finder drags are unverified until §8 is run (the whole AppKit path up to `NSDraggingInfo` is tested
  offscreen; global-event delivery during another app's drag is the main unmeasured assumption).
* Drag pass-through on the panel's transparent pixels (§3 "Hit shape") relies on AppKit's click-through for
  non-opaque windows whose `ignoresMouseEvents` was never set; it cannot be observed without real input (§8 step 9).
  Worst case, only the disc square's corners and the caption strip beside the pill would still swallow a drop.
* VoiceOver announcements from an accessory (background) app may not be spoken by every VoiceOver
  configuration (§8 step 18b).
* Esc without Input Monitoring is detected only when the pointer is over the wheel (exit heuristic); otherwise
  the wheel closes at the mouse-up.
* Modifier combos with Control/Command cannot work on macOS (AppKit operation masks).
* Runtime on macOS 14 itself not tested here (deployment target 14.0 verified with `vtool`; Swift libraries newer
  than 12 are weak-linked); x64 verified under Rosetta 2 only.
* File promises (Photos, Mail attachments) are unsupported by design (no file exists before the drop). An item
  that offers a real file URL *and* promise types is taken as the file (the source states it exists; main still
  validates it) — pinned by a test so a change of this rule is deliberate.
* Sleep, screens asleep, user switch, screen lock and display removal are verified with the real notification
  wiring in-process (posted to the helper's own centres; the lock with a uniquely named distributed notification),
  not with a real lock/sleep/unplug (§8 step 21).
* Secure Event Input (a password field or Terminal's Secure Keyboard Entry active during the drag): whether
  `NSEvent.modifierFlags` still reports Shift/Option and whether Esc is seen cannot be measured without real input
  (§8 step 22). Mouse monitoring is unaffected (it is not keyboard input).
* Finder aliases named like a supported file get a menu; main's header check refuses them after the drop with the
  alias hint (the helper never reads file contents).
