Code signing policy

Last updated: 12 November 2026

  • This page explains who signs OrbitDrop's installers and executables, and how.
  • Windows: prepared for SignPath Foundation's free code signing for open source projects. The current state is the first line of the Windows section below.
  • macOS: signed with the developer's own Apple Developer ID and notarized by Apple. SignPath is not involved.
  • Only files built on GitHub-hosted build machines from tagged commits of this repository are signed, and every release is approved by a person.

Windows

Current state: the Windows installers are not code-signed yet (their file names contain -unsigned). The project has applied to SignPath Foundation for free code signing; once it is accepted, the next releases are signed as described below. Until then, the statement below is a plan.

Free code signing provided by SignPath.io, certificate by SignPath Foundation

Windows shows files signed this way with SignPath Foundation as the publisher. The certificate is issued to SignPath Foundation and the signing happens inside the SignPath.io service, so the OrbitDrop developer never holds the signing key.

What is signed

Only files made from the sources and settings of the OrbitDrop repository are signed.

Signed Windows files
FileWhat it is
OrbitDrop.exeThe app executable. electron-builder makes it from the Electron runtime with this repository's settings (icon, version information, Electron fuses).
resources\helper\OrbitDropHelper.exeThe global drag helper, built from this repository's C++ sources (native/windows).
OrbitDrop-<version>-win-x64-setup.exeThe installer (NSIS).
Uninstall OrbitDrop.exeThe uninstaller (NSIS). It travels inside the installer and is placed in the installation folder.

All four carry the product name OrbitDrop and the release version (for example 1.0.1) in their version information. The build scripts check this, and SignPath checks it again before signing; if any file differs, nothing is signed.

What is not signed

These files are made by other projects. They are included exactly as those projects publish them, and OrbitDrop does not sign them:

  • Electron (Chromium): ffmpeg.dll, d3dcompiler_47.dll, dxcompiler.dll, dxil.dll, vk_swiftshader.dll, vulkan-1.dll
  • sharp and libvips (image processing): sharp-win32-x64-<version>.node, libvips-42.dll, libvips-cpp-<version>.dll
  • @napi-rs/canvas (Skia, PDF rendering): skia.win32-x64-msvc.node

Their licences and origins are listed in the third-party licences.

How a signed release is made

  • The files to sign are built by the Release workflow on GitHub Actions, on a GitHub-hosted Windows build machine, from a tagged commit (a version tag starting with v) of this repository (github.com/keilvher1/orbitdrop). Files built on a personal computer are never signed.
  • The workflow uploads the files to sign as a GitHub workflow artifact and then asks SignPath to sign them. SignPath checks with GitHub directly that the request comes from this repository's workflow (build origin).
  • For every release, the approver listed below reviews the signing requests in SignPath and approves them by hand; nothing is signed without that approval. A release has two requests: first OrbitDrop.exe, OrbitDropHelper.exe and the uninstaller, then the installer that contains them.
  • The signed installer goes to a draft release, which a person checks before publishing it. The files of a published release are never replaced.

Only people with commit access accept changes, and changes from anyone else (pull requests) are merged only after review. Build scripts and CI configuration count as source code and are handled the same way. Every member must protect their GitHub and SignPath accounts with multi-factor authentication (MFA).

Privacy

OrbitDrop's privacy statement (한국어) applies. The only feature that connects to a system the user did not choose is the automatic update check (GitHub); it never sends files, file names or usage data. The Windows installer (from 1.0.1) shows this during installation and offers an option to turn the automatic update check off (/NOUPDATECHECK for unattended installs). It can also be turned off in the welcome window shown on the first run and in Settings › General.

macOS

The macOS DMGs and the app are signed with the developer's own Apple Developer ID certificate and notarized by Apple. SignPath is not involved, and the signing key lives only in the keychain of the release Mac.

How to check

  • Windows: open the installer's Properties › Digital Signatures in File Explorer, or run Get-AuthenticodeSignature .\OrbitDrop-<version>-win-x64-setup.exe in PowerShell. A signed file shows the status Valid and SignPath Foundation as the signer.
  • macOS: spctl -a -vv /Applications/OrbitDrop.app in Terminal reports source=Notarized Developer ID.
  • Every release has SHA256SUMS.txt with the SHA-256 of each file (see “Check the download” under Download).

Questions and changes

If a signed file does not match this policy, or something looks wrong, please report it in GitHub issues. If this policy changes, this page and its date are updated; earlier versions are in the change history on GitHub.
