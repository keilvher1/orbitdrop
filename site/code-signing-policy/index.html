코드 서명 정책

Code signing policy · 최종 수정일: 2026년 11월 12일

  • 이 페이지는 OrbitDrop의 설치 파일과 실행 파일을 누가, 어떤 절차로 서명하는지 설명합니다.
  • Windows: SignPath Foundation의 무료 오픈 소스 코드 서명을 받도록 준비했습니다. 지금 상태는 아래 Windows 항목의 첫 줄에 있습니다.
  • macOS: 개발자 본인의 Apple Developer ID로 서명하고 Apple의 공증을 받습니다. SignPath와는 관계없습니다.
  • 서명하는 파일은 이 저장소의 태그된 커밋을 GitHub이 호스팅하는 빌드 머신에서 빌드한 것뿐이며, 릴리스마다 사람이 승인합니다.

Windows

지금 상태: Windows 설치 파일은 아직 코드 서명이 없습니다(파일 이름에 -unsigned가 붙습니다). SignPath Foundation에 무료 코드 서명을 신청했으며, 승인되면 그다음 릴리스부터 아래 방식으로 서명합니다. 그 전까지 아래 문구는 계획입니다.

Free code signing provided by SignPath.io, certificate by SignPath Foundation

(SignPath.io가 무료 코드 서명 서비스를, SignPath Foundation이 인증서를 제공합니다.) 이 방식으로 서명된 파일은 Windows에서 게시자가 SignPath Foundation으로 표시됩니다. 인증서는 SignPath Foundation에 발급된 것이고, 서명은 SignPath.io 서비스 안에서 이루어지므로 OrbitDrop 개발자는 서명 키를 갖지 않습니다.

서명하는 파일

OrbitDrop 저장소의 소스와 설정으로 만드는 파일만 서명합니다.

서명하는 Windows 파일
파일무엇인가요
OrbitDrop.exe앱 실행 파일. electron-builder가 Electron 런타임에 이 저장소의 설정(아이콘, 버전 정보, Electron fuse)을 적용해 만듭니다.

네 파일의 버전 정보에는 제품 이름 OrbitDrop과 릴리스 버전(예: 1.0.1)이 똑같이 들어 있습니다. 빌드 스크립트가 이를 확인하고, SignPath도 서명하기 전에 다시 확인합니다. 하나라도 다르면 서명하지 않습니다.

서명하지 않는 파일

다른 프로젝트가 만든 아래 파일은 그 프로젝트가 배포한 그대로 넣고, OrbitDrop은 서명하지 않습니다.

  • Electron(Chromium): ffmpeg.dll, d3dcompiler_47.dll, dxcompiler.dll, dxil.dll, vk_swiftshader.dll, vulkan-1.dll
  • sharp와 libvips(이미지 처리): sharp-win32-x64-<버전>.node, libvips-42.dll, libvips-cpp-<버전>.dll
  • @napi-rs/canvas(Skia, PDF 그리기): skia.win32-x64-msvc.node

이 파일들의 라이선스와 출처는 제3자 라이선스 목록에 있습니다.

빌드와 승인 절차

  • 서명할 파일은 GitHub Actions의 Release 워크플로가 이 저장소(github.com/keilvher1/orbitdrop)의 태그된 커밋(v로 시작하는 버전 태그)에서 GitHub이 호스팅하는 Windows 빌드 머신으로 빌드합니다. 개인 컴퓨터에서 빌드한 파일은 서명하지 않습니다.
  • 워크플로는 서명할 파일을 GitHub 작업 산출물로 올린 뒤 SignPath에 서명을 요청합니다. SignPath는 그 요청이 이 저장소의 워크플로에서 왔는지(빌드 출처)를 GitHub에서 직접 확인합니다.
  • 릴리스마다 아래의 승인 담당자가 SignPath에서 서명 요청을 확인하고 직접 승인해야 서명됩니다. 한 릴리스에 요청이 두 번 있습니다: 먼저 OrbitDrop.exe·OrbitDropHelper.exe·제거 프로그램, 그다음 이 파일들을 담은 설치 프로그램입니다.
  • 서명된 설치 프로그램은 초안 릴리스에 올라가고, 사람이 확인한 뒤에 공개합니다. 이미 공개한 릴리스의 파일은 바꾸지 않습니다.

개인정보

OrbitDrop의 개인정보 처리방침(English)이 적용됩니다. OrbitDrop이 사용자가 지정하지 않은 곳에 연결하는 기능은 업데이트 자동 확인(GitHub) 하나뿐이며, 파일·파일 이름·사용 기록은 보내지 않습니다. Windows 설치 프로그램(1.0.1부터)은 설치하는 동안 이 내용을 보여 주고 업데이트 자동 확인을 끄는 선택지를 줍니다(무인 설치에서는 /NOUPDATECHECK). 처음 실행할 때 열리는 환영 창과 설정 › 일반에서도 끌 수 있습니다.

macOS

macOS용 DMG와 앱은 개발자 본인의 Apple Developer ID 인증서로 서명하고 Apple의 공증(notarization)을 받습니다. SignPath는 관여하지 않으며, 서명 키는 릴리스용 Mac의 키체인에만 있습니다.

확인하는 방법

  • Windows: 파일 탐색기에서 설치 파일의 속성 › 디지털 서명 탭을 보거나 PowerShell에서 Get-AuthenticodeSignature .\OrbitDrop-<버전>-win-x64-setup.exe를 실행합니다. 서명된 파일이면 상태가 Valid이고 서명자가 SignPath Foundation입니다.
  • macOS: 터미널에서 spctl -a -vv /Applications/OrbitDrop.app을 실행하면 source=Notarized Developer ID가 나옵니다.
  • 모든 릴리스에는 각 파일의 SHA-256이 담긴 SHA256SUMS.txt가 있습니다(다운로드의 ‘내려받은 파일 확인하기’).
